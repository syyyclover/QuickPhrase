# 口径生成器 QuickPhrase

把重复劳动交给模板：选几个下拉、填一两个空，一段结构固定、措辞统一的文案就生成好了，
按 `Ctrl+Enter` 复制走。常驻系统托盘，全局热键（默认 `Alt+Q`）随时唤出。

纯 **C11 + Win32 API + cJSON** 实现，无 Electron / 无浏览器内核 / 无运行时依赖，
静态链接单文件 exe，几百 KB。解析规则支持四种取法（按分隔符取段 / 包含关键词 /
取两标记之间 / 正则表达式），正则引擎是自带的，不引入任何第三方库。

## 1. 交付物

| 文件 | 说明 |
| --- | --- |
| `dist/QuickPhrase-3.3.0-setup.exe` | **安装包**（自带界面向导，内嵌主程序与卸载器） |
| `dist/QuickPhrase.exe` | 免安装绿色版主程序（可直接双击运行） |

安装包只写 `HKEY_CURRENT_USER` 与用户目录，**不需要管理员权限、不弹 UAC**，
默认安装到 `%LOCALAPPDATA%\Programs\QuickPhrase`。
安装向导可选：桌面快捷方式 / 开始菜单 / 开机自动启动 / 安装后立即运行。
卸载可从「设置 → 应用」或安装目录里的 `uninstall.exe` 进行，卸载时会询问是否保留模板数据。

命令行开关：

QuickPhrase.exe --tray     强制静默驻留托盘（开机启动项用的就是这个）

QuickPhrase-3.3.0-setup.exe /S    静默安装到默认位置

## 2. 数据位置

主界面「文件 → 导入 / 导出」可把所有模板打包成一个 JSON 交换，导入支持**合并**（同 id 覆盖、新 id 追加）

> 数据兼容：v3.3 可读取旧版 JSON；逐段处理、不计入输出、批量、表格输出、正则解析规则等
> 新增字段均为可选，缺少相应开关时默认关闭。旧版程序可能忽略新字段，无法保证新规则的
> 输出语义——例如用旧版打开带正则解析规则的模板时，`"type": "regex"` 会被当成
> `split` 读取（不会报错、也不会丢别的字段，只是那条规则不再按正则生效）。

> 空来源不命中除“为空”之外的条件，取反也不命中；未配置显式默认值的单选初始为空。
> 因此旧数据仍可读取，但依赖上述旧行为的模板需要检查规则或补充显式默认值。
> v3.2 只做加法：新增第四种解析规则（正则）与表格预览的呈现方式，取值优先级、
> 规则语义与 JSON 结构均未改动，旧模板行为不变。
> v3.3 同样只做加法：预览控件文本模式支持拖选/双击选词/Ctrl+A/Ctrl+C/右键菜单，
> 「未匹配」提示的位置与语义不变，数据格式一字未动。

## 3. 使用速览

- 左侧是模板树，支持分组（文件夹）、拖拽模板进分组、搜索框实时过滤（模板名 / 片段标签 / 固定内容都会被搜）。
- 右侧是生成区：模板里定义的每个片段会变成一行控件——
  文本片段 → 输入框（可勾「多行文本」给大文本框），单选片段 → 下拉框，
  多选片段 → 勾选弹层（结果按分隔符拼接），时间片段 → 输入框 + 「现在」按钮
  （打开时自动填当下时间，格式可配）。勾了「隐藏」的变量不在这里出现，只由规则填。
- 同一个模板可以同时开最多 9 份互不干扰的填写：生成区上方的标签条，`Ctrl+T` 新开、
  `Ctrl+1~9` / `Ctrl+Tab` 切换、双击改名、右键可复制这一份或换颜色。
  长时间的两地并行管控不用来回重填（当前只在内存里保存，退出程序不保留）。
- 下方预览区默认是等宽字体（Consolas）的文本，任何输入变化都会立刻重算。每次选择模板
  默认显示「普通文本」；模板配置了表格输出时可切到「表格」，切换只改变预览口径，不改输入值。
  **文本预览可以像普通文本框一样拖选**：按住左键拖、双击选一段、`Ctrl+A` 全选、
  `Ctrl+C` 复制选中的那段，右键还有「复制选中 / 全选」。
  **没匹配上的地方会在预览里插一个红底红字的「失败」提示**——注意这是**插进去的提示**，
  不是去认正文里的字：你的数据里本来写着「失败」二字，也不会被标色；哪几处该提示，
  由引擎算出来的「空值位置」决定。
  **表格预览是一张真正的表格**：按列对齐、带列名表头、浅网格与隔行底色，横向纵向都能滚；
  某一格没取到值（解析规则没命中）时，那里会用红字标出「未匹配」。
  预览区和左侧模板树之间那两条分隔条都可以拖（预览高度会记住），双击恢复默认。
- **模板编辑器里的「默认值预览」是同一个控件、同一套样式**：同样能切「文本预览 / 表格预览」，
  表格一样对齐带表头，文本一样能拖选、一样把没匹配上的地方标出来。改一条规则立刻能看到效果，
  不用保存回主界面再看。
- 模板编辑器窗口可以拉大、最大化（大小会记住），里面的预览区也能上下拖、双击恢复默认，
  改长模板时不用再挤在一个小窗里；保存时会自动做一次**模板体检**，见下。
- `一键复制文本/表格` 或 `Ctrl+Enter` 把**当前预览模式**的内容以 Unicode 文本写入剪贴板，
  按钮会短暂变成「✓ 已复制」。表格模式复制的列间是实际 Tab，可直接粘贴到 Excel / 在线表格。
- `Ctrl+F` 聚焦搜索，`Ctrl+N` 新建模板，`Ctrl+E` 编辑当前模板，`Ctrl+R` 重置输入，`Esc` 收回托盘。
- 关闭窗口 = 隐藏到托盘；真正退出请用托盘右键菜单「退出」。

### 模板里的四种自动填充

**解析规则**（挂在文本片段上）：从用户输入里抽取信息，自动填进别的变量。

规则引擎不识别、也不依赖任何内置业务字段；下面的设备编号只是示例。解析、条件、引用与
表格拼接都可以用于任意模板、任意变量名和任意文本内容。

- *按分隔符取段*：输入 `SN-A12-BJ-DBS-01`，用 `-` 分割取第 4 段 → 得到 `DBS`，写入「机型」变量。
- *包含关键词*：输入里出现 `DBS` → 把「机型」直接填成 `DBS 系列`。
- *取两标记之间*：在「前标记」之后、「后标记」之前取子串——`网络设备XXX经核查` 里前标记填
  `网络设备`、后标记填 `经核查`，就把中间的设备名取出来（前标记留空 = 从头取，后标记留空 = 取到末尾，
  大小写不敏感）。夹在两个不同词之间、单个分隔符切不出来的元素，一步就能拿到。
- *正则表达式*（第四种类型）：前三招都是从固定位置切，遇到「位置不固定、但形态固定」的内容
  就得靠它。`设备编号[:：]\s*([A-Za-z0-9\-]+)` 一句就能把编号抠出来，不管它前面排着多少别的字。
  写法是标准正则：`.` `*` `+` `?` `{m,n}` `[]` `[^]` `()` `(?:)` `|` `^` `$`，以及
  `\d` `\w` `\s`（各有大写取反版）和 `\1`…`\9` 反向引用；量词也支持懒惰写法
  （`*?` `+?` `{m,n}?`）。「捕获组」填 `0` 取整个匹配，填 `1`、`2`… 取对应括号里的那部分：
  上面那条配捕获组 `1`，拿到的是编号本身而不是「设备编号：」。匹配同样**大小写不敏感**，
  `\w` 认得中文、`\s` 连全角空格也算。
- 任一种解析规则都可勾「逐段处理」：源变量里是多段话（换行分隔）时，对每一段各抽取一次，
  空白段会跳过，命中的结果再按行合并——一个变量里粘进好几段告警，就能逐段生成、结果分行。
- 来源为空、只有空白，或从有内容改为空时，解析规则一律不命中；旧的派生值会立即清掉，
  目标回到手填值或显式默认值，都没有时就是空，不会保留上一次命中的结果。正则取到空串
  也按未命中处理；模式写坏了（括号不配对之类）既不命中也不会崩，保存时体检会指出问题位置。

#### 正则引擎的验证情况

正则引擎是自带的（`src/regex.c`，纯 C、无第三方依赖），并做过**差分验证**：`tests/regex_diff.py`
随机生成大批 (模式, 文本)，把本引擎的结果与 Python 的 `re`（`IGNORECASE` + `search`）逐字节比对。

- **「实际会写的那类模式」100% 一致**（4000 条，硬门槛）。生成时会排除「把量词套在可空分组上」、
  反向引用、超过 2 层分组嵌套这些容易被引擎实现细节放大的写法。
- 另有 4000 条「乱组合」压力用例，只断言必定返回且两次运行结果相同——实测 0.1 秒内跑完。
- 这套差分验证一路揪出并修掉了几个真问题：分支只试第一条、`*` / `?` 零次量词的编译、
  可空分组嵌套量词的回退、字符类大小写折叠（`[@-_]` 认不认小写 `b`）、
  以及「一个起点上的病态回溯把后面所有起点的机会一起吃掉」。
- 已知边界：把量词套在**可空分组**上再层层嵌套、同时掺反向引用的极端写法，个别情况下
  捕获组的取值会与 Python 不同（压力档实测 0.07%）。这类写法在真实模板里不会出现；
  引擎自带步数预算与回溯栈上限，因此无论模式多离谱都**不会卡住界面**，最差是判不命中。

**条件规则**（挂在任意片段上）：根据别的变量的值改写本片段的输出。

- 一条规则 = 若干条件项（`[变量] [关系] [匹配值]`）+ 组合方式（全部满足 / 任意满足）+ 结果值。
- 关系支持 包含 / 等于 / 开头是 / 结尾是 / 属于其中之一 / 为空，每项还可勾「不满足」取反，
  于是「不包含」「不为空」之类不需要额外的关系类型。多条规则按列表顺序优先，命中即止。
- 来源为空或只有空白时，只有「为空」能命中；「不为空」不命中，其余关系即使勾了「不满足」
  也不命中，避免空输入凭空触发规则。
- 条件规则挂在文本、单选、多选或时间变量上时，结果值可以写 `{变量名}`，把多个已求值字段
  组合进这个变量。例如一个隐藏且「不计入输出」的助手变量可写 `{厂商}-{设备}`，再由表格格式
  引用 `{助手}`。这里只展开一层；手填值、默认值、解析结果和引用得到的花括号仍按字面保留。

**引用**（挂在任意变量上）：本变量的值直接取自另一个变量，整体或其中一部分。

- 电话号码填在前面，后文要复述尾号 → 引用它、取「第 8 个字起 4 个」，不用手填两遍。
- 取法有 整体 / 按分隔符取第 N 段 / 从第 N 个字起取 M 个 三种；引用的目标始终跟着来源走，
  在填写界面是只读的。

四者会反复求值直到稳定（最多 8 轮），所以可以串联。同一个变量有多个来源时，
优先级是 **条件规则 > 解析规则 > 引用 > 手动填写 > 默认值**——变量匹配的结果压过手滑
点错的那一下；规则这一轮不再命中时，手填的内容会重新露出来。这里的默认值必须在模板里
显式设置：单选即使列了选项，也不会擅自把第一项当默认值；没有手填和显式默认值时就是空。

### 输出格式里的占位符与转义

固定片段正文和模板级 `tableOutputFormat` 都可以写 `{变量名}`，生成时换成那个变量此刻的值：

| 写法 | 结果 |
| --- | --- |
| `{电话}` | 换成「电话」变量当前的值（按变量名找，大小写不敏感） |
| `{{` | 输出一个字面的 `{` |
| `\t` / `\n` | 制表符 / 换行；这里键入的是两个字面字符，生成与复制时才变成真实 Tab / 换行 |
| `\\` | 输出一个字面的 `\`；其余认不出的 `\x` 原样保留 |
| `{没有这个变量}` | 原样保留，好让写错的地方看得见 |

以前要复述一个已经填过的值，得再建一个隐藏变量去引用它；现在直接写在句子里就行，
一段固定话术里引用五六个变量也只是五六个花括号。占位符换进来的内容不会再被当成占位符
二次展开，所以用户自己敲进变量里的 `{`、`\t` 永远是字面量。占位符也可用于非固定变量的
条件规则结果，以便先组合一个隐藏助手字段；默认值、解析结果、引用值不会因此被再次解释。

### 普通文本与表格输出

普通文本仍按模板片段顺序拼接，并跳过勾了「不计入输出」的变量；这是每次选中模板后的默认模式。
表格是同一模板的第二种独立输出：在模板编辑器勾「启用表格输出」，然后直接编写表格格式，
也可用「插入变量」在光标处插入 `{变量名}`。例如：

```text
{列A}\t{列B}\t{列C}
```

格式框里看到的 `\t` 是反斜杠加字母 t；预览和剪贴板里则是一个实际的 U+0009 Tab，
不是若干空格。预览框里的视觉宽度不代表单元格边界，以粘贴到表格软件后的分列结果为准。

表格格式直接读取全部变量的求值结果，不依赖片段顺序，也不受「隐藏」或「不计入输出」限制。
因此推荐的拆表流程是：用解析规则提取各列，需要时用条件结果占位符组合助手字段，再由
`tableOutputFormat` 明确排列各列。派生字段可以同时勾「隐藏」和「不计入输出」，让填写区和
普通文本保持清爽，表格仍能引用它们。旧模板把 `{列A}\t{列B}` 放在末尾固定片段的做法仍兼容，
但只会成为普通文本的一部分，不再是新模板的首选表格机制。

**批量**（模板头部的开关 + 「源变量」下拉）：一次粘进多段 / 多行的原始告警时，勾上批量、
选一个文本变量作源，渲染时会把源按行拆开、**每一行各跑一遍规则**：普通模式每行生成一份
普通文本，表格模式每行生成一行表格，最后按换行合并。填一次就固定的常量列逐行不变，
靠解析规则 / 引用 / 条件组合从源派生的列逐行变化。
空白行会跳过；某个非空行抽取不到字段时仍会保留这一行，未命中的列按正常优先级回落到手填值
或显式默认值，两者都没有才为空。空源或单行源按普通单次渲染处理，批量完成后填写框仍保留
原始整段输入。（把派生的「列变量」设为隐藏更清爽——它们只为拼行服务。）这些行为同样是
通用模板能力，不与示例模板或特定字段绑定。

### 保存时的模板体检

规则一多，「配好了但永远不会生效」的规则很难自己发现——表现只是输出里少了一段。
保存模板时会自动跑一遍体检，把这几类挑出来提醒（只提醒，不阻止保存；选「否」会跳到
出问题的那个片段）：

- 条件永远不成立：触发变量的取值能穷举时，逐个代进引擎自己的判定函数，全都不成立就报，
  并列出它实际可能的取值；
- 条件项 / 解析规则指向的变量已被删除，或还没选；
- 正则解析规则没填模式，或模式语法有误（会指出第几个字符附近出的问题）；
- 规则没有任何条件项，或结果值是空的；
- 开了批量却没选源变量，或选的源变量已被删除 / 不是文本变量；
- 固定内容或表格格式里有认不出的占位符；
- 开了表格输出但格式为空、变量名不唯一，或格式没有 `\t` / 实际 Tab 分列符。

判断用的是引擎那一份代码，所以体检和实际生成不会有两套说法；穷举不了的（能手打的文本、
多选的组合、时间串、被别的规则接管的变量）一概不报——宁可漏报，不冤枉一条好规则。

## 4. 从源码构建

需要 MinGW-w64 交叉编译器（Linux 上 `dnf install mingw64-gcc` 或 `apt install gcc-mingw-w64-x86-64`）
与 Python 3 + Pillow（只用于生成 `.ico`，`res/*.ico` 已随源码提供）。

```bash
make            # 主程序 + 卸载器 + 安装包，产物在 dist/
make app        # 只出 build/QuickPhrase.exe
make test       # 在本机运行引擎、存储与启动策略自检（不需要 Windows）
make size       # 看产物体积
make clean
```

手工编译（等价于 `make app`）：

```bash
x86_64-w64-mingw32-windres -c 65001 -I. -Isrc resource.rc -O coff -o build/resource.res
x86_64-w64-mingw32-gcc -std=gnu11 -O2 -municode -mwindows -s -static -Isrc \
    src/main.c src/ui.c src/ui_dialogs.c src/preview.c src/textview.c src/engine.c \
    src/storage.c src/cJSON.c \
    src/regex.c src/launch.c \
    build/resource.res -o build/QuickPhrase.exe \
    -luser32 -lgdi32 -lcomctl32 -lshell32 -ladvapi32 -lcomdlg32 -luxtheme \
    -lole32 -loleaut32 -luuid -ldwmapi
```

## 5. 源码结构

```
src/engine.c   .h    数据模型 + 规则引擎，纯 C，不含任何窗口 API → 可独立单测
src/storage.c  .h    cJSON 读写 data.json / settings.json、UTF-8↔UTF-16、导入导出
src/main.c           WinMain、单实例、托盘、全局热键、主题、开机启动
src/ui.c             主窗口：模板树、动态字段区、实时预览、复制、深色模式
src/ui_dialogs.c     模板编辑器、解析/条件规则对话框、设置、关于、输入框
src/preview.c  .h    口径预览控件（文本 / 表格两种呈现，自绘；主界面与编辑器共用）
src/textview.c .h    预览用纯文本排版内核（提示插入 / 折行 / 命中，纯 C → 可独立单测）
src/regex.c    .h    内置正则引擎（回溯虚拟机，纯 C，无第三方依赖）→ 可独立单测
src/cJSON.c    .h    第三方 JSON 库（MIT）
installer/           安装程序与卸载程序（同样是原生 Win32 C）
tests/               排版、正则、引擎、存储与启动策略的自检 + 正则差分验证
```

界面全部用原生控件（Edit / ComboBox / TreeView / ListView / Button）手工布局，
按 DPI 缩放；深色模式走 uxtheme 的 `DarkMode_Explorer` 主题与 `DwmSetWindowAttribute`，
在不支持的旧系统上自动退回浅色，不会报错。

## 6. 仓库目录

```
QuickPhrase/
├── src/            源码（见上一节的清单）
├── installer/      安装程序 / 卸载程序
├── res/            图标与程序清单
├── tests/          本机自测（引擎、存储、正则、排版、启动策略）+ 正则差分验证
├── tools/          mkicon.py（由 res/app.png 生成 .ico，构建不依赖）
├── docs/           设计稿与实施计划（superpowers 格式）
├── examples/       验收用的样例输入（示例告警、截图；不参与编译、不进安装包）
├── data.json       一份真实的模板数据快照（仅作验收夹具，见下）
├── QuickPhrase-模板.json  可供导入的模板文件
├── README.md       本文件
├── QuickPhrase.md  开发需求与设计说明（本地保留，不进版本库）
├── Makefile        构建脚本
└── build/ dist/    构建中间件与产物（make clean 可清，不进版本库）
```

`data.json` 与 `QuickPhrase-模板.json` 是**验收夹具**：测试会读它们检查规则语义与
表格输出，但它们**不会**被编进软件本体或安装包 —— 安装包只内置两个测试模板，
应用首次运行时在 `%APPDATA%\QuickPhrase` 生成。
