## 本轮证据与修改

发现并复现一个独立绘制缺口：主窗口、填写区、预览及会话标签仅响应 `WM_PAINT`，没有响应系统向指定 DC 请求绘制的 `WM_PRINTCLIENT`。回归使用初始为空的目标 DC，旧代码不写入该 DC；不是正常绘制后等待再截图的检查。

依据 [WM_PRINTCLIENT 官方说明](https://learn.microsoft.com/en-us/windows/desktop/gdi/wm-printclient)，默认窗口过程不处理该消息，应使用调用方提供的 DC 绘制完整客户区，不调用 BeginPaint／EndPaint。[AnimateWindow 官方说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-animatewindow) 也要求窗口及其子窗口支持取图绘制。**这能证明缺失的接口路径，不能证明用户机器的 DWM 最大化动画必然经过该路径；它与本次偶发黑闪的关系仍需原生压力验收。**

- 主窗口普通绘制与指定 DC 绘制共用同一个带缓冲的背景／分隔条渲染器。填写区复用背景绘制；不消耗待处理的正常绘制区域。
- 预览和会话标签沿用原模型、几何与绘制逻辑，新增指定 DC 的入口，保存／恢复调用方 DC 状态；缓冲失败直接绘制完整内容。保留用户已验证的编辑器拖动修正与新增功能。
- 独立只读审查发现表格直接绘制回退曾替换调用方裁剪区域，现改为与原裁剪区域相交并恢复。DC 状态保存失败时保留调用方裁剪区域。回归执行实际表格绘制函数，检查限定区域之外的像素不被修改。
- 未关闭系统动画，未设置整窗 `WS_EX_COMPOSITED`，未更改主题、规则、数据、时间或选项填写行为。
