## 验证结果

2026-10-07 的最终检查：

- `make -j4 test`：启动修复后 9 个 C 测试程序、15 个 Python 检查全部通过。具名统计项共 1099 项；另有断言式回归。两组真实业务夹具缺失而跳过。
- `make -j4 sanitize`：C 核心 ASan/UBSan 与泄漏检查通过；此前发现的两处测试自身泄漏已修正。
- 正则实际模式 4000 条与 Python 一致；压力档 4000 条均及时返回且结果可重复，其中 3 条捕获差异属于已知边界。
- 主程序、卸载器、安装器及 Win32 检查程序交叉编译通过，无编译警告；三个交付程序的 PE 文件版本均为 `3.5.0.0`。
- 两个 ICO 均包含 16/20/24/32/40/48/64/128/256px 九个尺寸；`git diff --check`、Python 语法和快照 shell 语法检查通过。
- 初次独立审查提出四项 Important，均补充失败测试后修复。随后用户反馈启动失败，发现此前漏检的无效 manifest；启动修复和新增资源校验结果见下节。

相关日志在 `build/acceptance-tests.log`、`build/acceptance-sanitize.log`、`build/acceptance-build.log`。API 模拟检查不等同于原生 Windows 验收。

已知环境限制：Wine 8.0 在隔离 profile 初始化时报告 `user32.dll.CreateDialogParamW` 未实现和 `kernel32.dll` 加载失败（`c0000135`）；默认 Wine 与显式 wine64 均未能运行窗口测试。

两组真实业务夹具不在工作区，相关验收明确跳过。正则压力档允许已知的极端模式捕获差异，实际模式档要求与 Python 逐条一致。

## 启动阻断修复（2026-10-07）

用户反馈双击无法打开。检查确认上一轮发布将两个独立 XML manifest 的版本属性误写成了未展开的 C 宏 `version=QP_FILE_VERSION_STR`，主程序、安装器和卸载器均内嵌了无效 XML。此前只验证 PE VERSIONINFO 和编译成功，未检查 RT_MANIFEST，漏掉了加载阶段的错误。

修复为带引号的四段版本 `version="3.5.0.0"`。新增 `tests/manifest_validation.py`：旧源文件及三个旧可执行文件全部失败；修复后检查源 XML 和 PE 中真正内嵌的 RT_MANIFEST。Makefile 在资源编译前检查源文件、程序编译和打包后检查内嵌资源，避免编译成功但无法启动的包再次交付。

修复后重新构建所有可执行文件、重新运行完整回归，并更新 SHA-256；版本号仍为 3.5.0。Windows 实际运行仍以真实系统验证为准。

修复后的 `build/startup-fix-build.log` 与 `build/startup-fix-tests.log` 记录无警告构建、完整回归和内嵌资源检查。再次尝试 Wine 后仍在 profile 初始化时失败（退出码 53），日志为 `build/startup-fix-win32.log`，不能据此声称已完成原生启动验收。
