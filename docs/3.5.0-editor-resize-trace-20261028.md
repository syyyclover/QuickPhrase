# 编辑器卡顿尚未解决：耗时采集

用户复测 `editor-resize-perf-20261028` 后确认拖动边框、双击最大化仍明显卡顿，主界面没有同样问题。上一轮减少重复重绘的修改不能视为解决卡顿。

进一步代码检查：主界面和编辑器都会在布局完成后同步绘制；编辑器还有属性区滚动条稳定化的多轮布局，以及最大化时独有的 cloak/present 事务。仅凭代码不能确定哪一项占据实际耗时，需要原生操作时的分段计时。

`tools/build_resize_trace.py` 将当前源码复制到 `build/editor-resize-trace/source/` 后，仅对副本加入计时；不改变正式源码的显示行为。记录编辑器消息、布局、属性区摆位/滚动条、同步绘制，以及 GDI/DWM 等待。时间段存在嵌套，不能把各行耗时直接相加。固定内存缓冲最多记录 65536 行，溢出计数写入日志；不采集模板、口径或数据表内容。关闭编辑器后写入程序同目录的 `resize-timing-进程号.csv`，采集时不写磁盘。程序目录须可写。

产物：`dist/editor-resize-trace-20261028/QuickPhrase.exe`。这是诊断程序，不是已经修复的发布版。退出旧托盘进程，打开诊断程序，在编辑器中拖边框和双击标题栏复现数次，再关闭编辑器，即生成日志。

本轮仅完成 Windows 本机工具链编译、内嵌 manifest/图标检查和差异空白检查；没有执行桌面自动操作、性能验收或完整 test/sanitize/setup。正式逻辑未再修改。下一步以实际日志区分布局、控件绘制和 compositor 等待，定位后再修复。
