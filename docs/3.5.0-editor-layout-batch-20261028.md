# 编辑器布局中间绘制修正

用户手工采集的 `dist/editor-resize-trace-20261028/resize-timing-26448.csv` 包含 119 次布局，总计 5414.11ms，平均约 45.5ms，最长 112.93ms。2015 次根窗口 WM_ERASEBKGND 中有 608 次发生于外层控件几何提交期间。DWM 等待共 9 次，最长约 5.28ms；日志不支持将 DWM 等待认定为主要瓶颈。属性布局 pass 数与布局次数相同，没有观察到反复稳定化排版。

消息计时含嵌套，不能相加；WM_SYSCOMMAND/WM_NCLBUTTONDOWN 的秒级耗时还包含系统拖动消息循环与用户按住鼠标的时间，不能当作 UI 单帧阻塞。

布局队列原先允许 SetWindowPos/EndDeferWindowPos 中间绘制，之后又显式失效控件、边框与父窗口，最终由布局结束时同步绘制。新增 SWP_NOREDRAW，让摆位阶段只修改几何；原有损伤标记和最终绘制保持不变。该修正位于共享队列，主窗口和其他使用队列的对话框也适用。背景真实擦除、位图失败回退、最大化 cloak/present 路径不变。

`layout_damage.py` 新增中间绘制计数断言，Linux 原实现失败、修正后通过，覆盖分配失败、原生批处理失败、不同父窗口及损伤范围。Windows 本机 GCC 的分配包装驱动先在已有分配存活断言失败，未将它算作新缺陷复现；红绿证据来自 Linux。`layout_fallback.py` 和完整 `make test`、默认 `make sanitize`（含泄漏检查）、`make setup` 顺序通过。两组业务夹具仍缺失，正则压力档既有差异及适配驱动警告保留。日志在 `build/editor-layout-batch-results/`。

## 用户第二轮计时反馈

`resize-timing-28992.csv` 记录 66 次布局，平均 44.479ms、P95 63.113ms、最长 117.635ms。外层几何提交平均 8.646ms，较首轮 119 次记录的约 14.5ms 降低，但完整布局均值从约 45.5ms 仅降至 44.5ms，不能认定整体卡顿已解决。几何期间仍有 277 次根窗口背景擦除，说明禁止默认摆位重绘不能消除控件内部请求的全部绘制。

原始进程日志随后追加到了 214 次布局，追加后的平均值为 49.124ms；不得把这两个不同操作样本的差异当作严格基准测试。当前仍需要用户对流畅度、最大化停顿与黑块的主观反馈，不能将“欧克”直接解释为验收通过。
