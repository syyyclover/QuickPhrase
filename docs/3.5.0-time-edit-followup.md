# 时间格式删除选区修正（2026-10-10）

用户反馈删除键修改时间控件时会变为全选。当前已修正**模板编辑器中的时间格式下拉框**；主窗口日期／时间填写框是另一条输入路径，尚待用户回答已发出的定位问题，不能将这次修正说成所有时间输入问题均已解决。

## 修改与回归

`ed_commit_format` 的手动输入路径原先直接刷新样例、重新布局和预览，没有保留输入后的光标／选区。新增回归通过 Win32 适配模拟可编辑 ComboBox 重排后选中全部文字，旧函数先在光标断言失败。修正为刷新前使用 [CB_GETEDITSEL](https://learn.microsoft.com/en-us/windows/win32/controls/cb-geteditsel) 取得位置，刷新期间使用已有 loading 闸门阻止同步通知重入，之后用 [CB_SETEDITSEL](https://learn.microsoft.com/en-us/windows/win32/controls/cb-seteditsel) 恢复。选择预设的路径保持原生行为。

- `tests/editor_time_selection.py`：删除、连续修改、选区替换、清空、加载闸门与选择预设通过。这里是 OS 适配，不是原生键盘验收。
- `tests/test_engine.c`：缺少 `yyyyMMdd` 预设先失败，补入后通过；固定日期 2025-02-03 输出 `20250203`。默认格式仍是 `yyyy-MM-dd HH:mm:ss`。
- `tests/test_win32.c`：增加隔离的时间片段，检查真实 ComboBox 子 Edit 的 Delete、Backspace、全选清空和重新输入后的光标及内容；原生测试 EXE 与内嵌 manifest 编译检查通过。当前没有运行 Windows 原生键盘验收。
- 独立只读审查没有发现具体问题；没有修改用户数据、规则优先级、选项库或配置目录。

`make -j4 test` 与 `make -j4 setup` 通过；初次构建有短暂文件 mtime 超前提示，稳定源码后再次执行完整测试及构建，最终记录见 `/tmp/qp-time-edit-test.log`、`/tmp/qp-time-edit-setup.log`。两组业务夹具仍缺失而跳过，既有正则压力捕获差异和 OS 适配未使用变量警告不变。消毒器验证以本轮日志为准，不复用旧版本结论。

本轮 `make -j4 sanitize` 的默认沙箱运行因 LeakSanitizer 不支持 ptrace 失败，日志 `/tmp/qp-time-edit-sanitize.log`；经批准在沙箱外重跑完整默认消毒器／泄漏检查通过，日志 `/tmp/qp-time-edit-sanitize-escalated.log`，未关闭泄漏检测。Python OS 适配不因此成为真实 UI 消毒器验收。

## 交付与未完成项
