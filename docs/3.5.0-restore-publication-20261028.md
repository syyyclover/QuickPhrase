# 窗口恢复呈现时机修正（2026-10-28）

## 原因与修改

上一轮 `restore-frame-20261028` 只补全子窗口擦除绘制，用户仍能通过快速点击任务栏或托盘看到黑块。此次原生消息跟踪发现：恢复过程中，首次背景擦除早于 `WM_SIZE`，也早于 `ShowWindow` 返回；在这些位置补一次重绘，仍可能让桌面合成器先显示未画完的子窗口。

`src/ui/main_window.c` 现在在 `WM_QUERYOPEN` 或隐藏窗口即将显示时，暂时使用 `DWMWA_CLOAK` 阻止窗口呈现在桌面；等默认窗口过程完成尺寸及布局消息，再同步绘制全部子窗口，执行 GDI/DWM 刷新后解除 cloak。解除失败时保留状态并用定时器重试，避免窗口留在不可见状态。无关的层叠顺序变化不会提前发布窗口。没有修改系统动画设置。

为保持既有程序体积上限，四个窗口类共用注册循环；类名改为只读字符数组，字符串、窗口过程、样式和主窗口图标不变。删除居中分支中未使用的窗口矩形读取。构建优化、资源和体积预算均未调整。

保留此前的数据表随 JSON 导出/导入和编辑器选项滚轮修复。版本仍为 3.5.0，manifest 为 3.5.0.0。

## 回归方法

新增 `tests/restore_publication.py`，使用生产函数和消息分支验证显示顺序、布局完成后释放、接口不支持时回退，以及解除 cloak 失败后的真实定时器分支。故障注入先复现丢失恢复路径，再验证修正。这是 API 适配检查，不是屏幕验收。

新增 `tests/test_restore_visibility_win32.c` 和 `tests/win32_desktop_capture.h`，在本机 Windows 创建真实生产窗口和合成数据模型，通过 DXGI Desktop Duplication 读取桌面合成后的像素。使用明亮底窗区分未显示窗口和黑色控件；按帧时间戳排除恢复前旧帧，每次恢复都要求捕获到已显示的客户区。测试不读取用户配置；设置和模型保存已替换为测试函数，不写用户数据。

旧基线的原生取帧测试捕获到 154 帧大面积黑块（1247 帧属于目标客户区），因此测试确实能检出该问题。候选实现随后分别检查浅色、深色、最大化及深色最大化。每种模式执行 20 次最小化恢复和 20 次托盘显示路径；显示路径连续调用三次以覆盖快速重复请求。检查窗口可见性、输入保留、GDI 句柄及屏幕黑块。

原生测试调用 `WM_SYSCOMMAND/SC_RESTORE`、`ShowWindow` 及生产 `app_show_main`，没有注入鼠标点击。不能把它称为所有任务栏/托盘人工操作已验收。

## 限制

- `DWMWA_CLOAK` 从 Windows 8 起支持。Windows 7 不支持时保留原有重绘路径，不能声称此次呈现修复覆盖 Windows 7。
- 屏幕测试在本机当前桌面、显示驱动和缩放环境运行。不同显卡、远程桌面、所有 DPI 档位及用户业务模板仍需人工验证；它检出大面积黑块，不能证明所有单帧细微绘制缺陷不存在。
- 本轮不包含安装覆盖升级、卸载验收。既有两组真实业务夹具缺失的跳过项及正则压力档已知差异应保留在完整日志中。

参考：[微软 DWMWINDOWATTRIBUTE 文档](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute)、[Desktop Duplication API](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/desktop-dup-api)。
