# 编辑器最大化黑块修复（2026-10-28）

用户反馈点击最大化或双击标题栏时出现黑块。原生桌面取帧测试使用独立合成模型和真实编辑器窗口，旧实现捕获到 214 个异常帧。根因有两层：编辑器和属性宿主的 `WM_ERASEBKGND` 返回成功却没有画入背景；系统在最大化的 `WM_SIZE` 布局之前，已经开始呈现窗口变化。

补全擦除后仍捕获到 6 个异常帧，说明事后补画不足以消除过渡黑块。消息跟踪确认 `WM_WINDOWPOSCHANGING` 时 `IsZoomed` 已更新，且早于第一次擦除和尺寸布局。现在只在最大化状态变化时暂缓桌面呈现，等待默认窗口过程完成布局，再绘制全部控件并刷新 GDI/DWM 后解除暂缓。普通边缘拉伸继续实时绘制。

主窗口与编辑器复用 `window_presentation.c`，每个窗口独立保存 pending 状态；解除失败保留定时器重试。主窗口和编辑器共用背景/分隔条缓冲绘制，保留 DC/位图分配失败的直接绘制回退，不调整系统动画、资源、构建优化或体积预算。

编辑器的擦除、取图和正常绘制共用同一 renderer；擦除和取图不消耗正常待绘制区域、不修改调用者 DC 裁剪。属性宿主擦除也实际绘制主题背景。

新增 `editor_resize.py`、`editor_paint.py` 和 `test_editor_resize_win32.c`。前两项为 OS 适配回归，后一项通过 DXGI 读取桌面合成后的画面，并核对可见性、模型、输入、裁剪、待绘制区域和 GDI 句柄。测试不读取用户配置，设置和模型保存被测试函数替换。

合并绘制代码前，候选版原生检查 265 项通过，48 次最大化/还原/拉伸未捕获到大面积黑块。最终发布构建结果见下方补充；本地工具链中一次屏幕测试出现 DXGI `887a0026` 访问丢失，记录为环境失败，不能作为通过证据。

验证日志、修改前源文件及取帧保留在 `build/editor-maximize-20261028/`。旧记录不等于用户业务模板人工验收；不同显卡、DPI、安装升级及缺失业务夹具仍有验证限制。Windows 7 不支持 cloak 时回退原有绘制路径。

最终产物放在 `dist/editor-maximize-20261028/`，版本保持 3.5.0 / manifest 3.5.0.0。复测时先退出托盘中的旧进程，再打开新程序。
