# QuickPhrase 3.5.0 深度修复 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for native execution, or superpowers:subagent-driven-development if the user selects delegated execution. Track steps with checkboxes in the three stage plans.

**Goal:** 在不删功能、保持兼容的前提下，完成已确认缺陷修复、全部产品引导规范化、性能与体积验证。

**Architecture:** 完整候选对象成功后提交；集中布局损坏区域和绘制降级；预览与复制使用同一份带状态输出。按职责拆成三个子计划，依下述任务顺序执行，最终统一审查。

**Tech Stack:** C11、原生 Win32、MinGW-w64、cJSON、Python 测试适配器、clang ASan/UBSan。

**Spec:** `docs/superpowers/specs/2026-10-07-quickphrase-350-hardening-design.md`（用户已确认）。

## Global Constraints

- C11＋原生 Win32；保留 Windows 7 构建目标，不升级 Per-Monitor DPI 感知。
- 保留旧 JSON、条件 > 解析 > 引用 > 手填 > 显式默认值、快捷键、便携及安装交付。
- 版本仍为 3.5.0；唯一源头 `src/platform/version.h`，manifest 同步四段版本。
- 不自动提交、推送、回退或删除原有工作区内容；继续当前工作区与分支。
- 不引入 GUI/国际化运行库；不重生成图标母图、不减少九种图标尺寸。
- 引导统一“模板、片段、变量、规则、数据表、输出文本、表格输出、填写会话”；保留产品名称和用户业务正文。
- 保存、克隆和导入仅发布完整候选；失配提示不能进入复制原文。
- 布局必须配对私有队列；共享固定临时夹具的测试串行执行。
- 主程序 ≤448 KiB，安装包 ≤576 KiB；同机五次中位数的核心热点相对 O2 退化超过 10% 时不采用优化组合。
- 真实 Windows 验收与算法/API 模拟、交叉编译分开报告；缺夹具或平台限制列为未执行。

阶段计划引用此节，约束逐字沿用，不得用子计划的省略改变要求。

## Review Focus

1. 分配失败时仍返回非空的残缺对象/JSON：必须失败并保留旧数据（A1、A2）。
2. 设置补偿失败或会话快照失败：不能丢新输入或虚报已恢复（A4、A5）。
3. 缓存刷新发生在求值借用指针仍有效时：不得悬空或混用代际（A6）。
4. 同一几何下自然绘制与完整重绘不同：测试不能先修复被测屏幕（B1、B2）。
5. 无变化刷新或复制发生在输入通知待处理时：保留阅读位置且复制最新完整结果（A8、C1）。

## 顺序与文件职责

| 阶段 | 计划 | 职责边界与交付 |
| --- | --- | --- |
| A | [数据与查表安全](2026-10-07-quickphrase-350-data.md) | 模型完整性、JSON、所有权、取消/回滚、精确键、缓存、空值、截断状态；每项失败回归 |
| B | [绘制与全量文案](2026-10-07-quickphrase-350-display-copy.md) | 自然绘制诊断、布局/滚动内核、工作区适配、文本绘制降级、引导清单 |
| C | [性能、减重与交付](2026-10-07-quickphrase-350-performance.md) | 基准、减少无变化重算、资源去重、编译对照、预算和最终检查 |

A 的内存/查表修复可先独立测试；A8 的带状态渲染供 B 的文案与 C 的预览复用。B1 的自然绘制测量必须先于 B2 的绘制修复；缺真实 Windows 时继续其他有证据的任务，但不得把残影验证标成通过。

实际执行顺序遵守已确认设计：A1–A5（数据/事务）→ B1–B3（绘制/工作区）→ A6–A8（查表/文本）→ B4（全量文案复核）→ C1–C3（性能/减重/交付）。文案清单在 A 开始时建立，行为相关项随修复同步更新，B4 最后检查完整覆盖。

不将一次生产代码大改当成一个任务：每个任务完成 RED → 最小实现 → GREEN → 相邻回归，记录状态后再继续。提交步骤改为保留工作区与记录差异，不执行 git commit。

## 检查点与执行方法

- [ ] 计划自检及用户审阅：确认覆盖已批准设计，选择执行方法。
- [ ] 完成 A1–A5，执行完整算法/事务回归，记录未执行原生操作。
- [ ] 完成 B1–B3，区分绘制候选修复与实际视觉验收。
- [ ] 完成 A6–A8 与 B4，核对查表/文本回归和所有引导项。
- [ ] 完成 C，执行默认 test/sanitize/setup、独立审查、资源/预算/校验和检查。
- [ ] 用户获得有证据的修复报告及候选产物，不收到“全部问题彻底解决”的无证断言。

推荐 Native：本会话主代理实施各项，最后独立审查。任务跨模块共享接口，单一实施者可减少接口协调；重要保存故障、自然绘制和体积门槛仍保留独立验证。另一选择是逐任务子代理实施与审查，审查更细但开销较高。当前仅写计划，尚未修改产品或替换发布包。
