# QuickPhrase 规则引擎、表格输出与回归修复设计

## 背景与目标

本次改动在保留现有 C11、Win32 API、cJSON 技术栈和旧模板兼容性的前提下，完成以下目标：

1. 将自然语言中的元素抽取、重排为以制表符分列的表格文本，支持一次粘贴多行输入。
2. 让“日间管控”模板第 19 个元素在单段和多段输入下，都按相同的严格规则填充第 5 个元素。
3. 修复模板规则编辑后预览不立即更新、编辑器预览分隔条拖动后 UI 错位、规则推导值在源输入清空后残留、普通双击首次启动不显示主窗口等问题。
4. 保留并验证模板保存前的逻辑体检。
5. 交付可直接导入的 JSON 模板，并使用 `示例完整.txt` 验证输出可直接粘贴到 Excel 或在线表格。

## 兼容性原则

- 新增 JSON 字段保持可选；旧数据缺少字段时维持旧格式可读取。
- 不改变模板、片段、解析规则、条件规则和引用的 ID 寻址方式。
- 不引入新的运行时或 UI 技术栈。
- 普通用户启动与开机自启动使用不同语义：普通双击显示主窗口，显式 `--tray` 才静默驻留。
- 固定内容、显式默认值和日期时间变量仍可在没有用户输入时显示；仅无来源的变量值必须为空。

## 规则引擎语义

### 空值与推导值生命周期

变量值继续按以下优先级求值：条件规则、解析规则、引用、手动值、显式默认值。删除“规则当前失配时回落到上次推导值”的 sticky 语义：当源输入被清空或变为不匹配内容，且目标没有手动值或显式默认值时，目标立即变为空。

会话切换仍保存用户实际输入。恢复会话后，由当前源值重新运行规则，而不是恢复已经失效的派生结果。这样既保留并行填写能力，也不会让旧解析结果脱离其来源继续存在。

无显式默认值的单选变量不再自动采用第一项；第一项只有在模板将它明确配置为默认值时才生效。

### 条件规则的空来源

除 `empty` 运算符外，条件来源为空时，`contains`、`equals`、`startsWith`、`endsWith` 和 `in` 均不命中；对这些结果取反也不使空来源变成命中。需要根据空值触发时，应使用 `empty`，需要“不为空”时使用取反的 `empty`。这能避免“空字符串不包含 SRV”一类形式逻辑在尚未输入数据时生成业务结论。

### 逐段解析

解析规则增加可选的 `perParagraph`。启用后，源文本按 CRLF/LF 行边界拆分，跳过空行，对每一非空行独立应用原规则，并将命中结果按换行合并。单段输入与关闭该选项时保持相同结果。

`split`、`contains` 和 `between` 三类规则均支持逐段处理。每一目标变量仍遵守现有的“第一条命中规则生效”优先级。

### 表格批量渲染

模板增加可选的批量开关和批量源变量。批量源必须是文本变量。批量开启且源含多行时：

1. 保存源变量完整文本。
2. 逐个非空输入行注入源变量。
3. 对该行完整运行解析、条件、引用和占位符求值。
4. 渲染一行输出。
5. 用换行连接各行，并恢复源变量的完整文本状态。

变量片段增加可选的“不计入输出”标记。源文本和中间列变量可以参与规则、引用及占位符，但不直接拼入结果。最终固定片段通过 `{变量名}\t{变量名}` 组合列，其中 `\t` 在固定片段中展开为实际 U+0009 制表符，`\n` 展开为换行，用户输入中的反斜杠序列不做二次解释。

## 真实模板迁移

### 日间管控

保留第 19 个元素当前的严格规则：使用 `-` 分割并取第 4 段，目标为第 5 个元素。仅为该规则启用逐段处理：

- 单段输入：第 5 个元素得到一个严格截取结果。
- 多段输入：逐行执行同一截取规则，第 5 个元素得到按行对应的多个结果。
- 空行跳过；某一行无法取到第 4 段时不产生该行结果，也不沿用旧结果。

其余 120 个元素及引用关系保持不变。

### 巡检表格模板

以“巡检数据”为多行批量源，并设为不计入输出。为资源池、任务名称、状态、级别、专业、完整设备编号、日期、跟进人、处理状态和问题描述配置可复用的解析/条件/默认规则。中间列变量设为不计入输出，最终固定片段按预期列顺序使用制表符组合。

对 `示例完整.txt` 的每个非空输入行生成且仅生成一个输出行。可从原文提取的字段必须保持原字词，不因重排而改写；业务常量列和显式默认列按模板配置输出。输出中的每个列分隔符必须是实际制表符，而不是若干空格或字面的 `\t`。

交付文件为可由 QuickPhrase 导入的 JSON，且不会覆盖用户的原始 `data.json`。

## 编辑器与预览

### 规则实时更新

片段文本、默认值、类型、隐藏/不计入输出、多行、选项、引用、解析规则、条件规则、批量开关和批量源的增加、修改、删除或排序，均在模型对象更新后调用同一默认值渲染入口刷新编辑器预览。刷新不依赖保存操作。

### 预览分隔条布局

编辑器布局以预览分隔条作为上半部内容的硬边界。拖高预览时：

- 片段列表高度夹在非负范围内。
- 属性和规则区域不得覆盖分隔条或预览控件。
- 超出可用高度的属性内容使用滚动或受边界裁剪的容器显示。
- 分隔条高度在最小值、最大值、窗口最大化、不同 DPI 下均统一夹取。
- 拖动时只重排一次统一布局，旧分隔条区域和新区域都被正确重绘。
- 双击分隔条恢复默认高度，设置仍按现有方式持久化。

## 启动行为

- 无参数启动：创建托盘图标后显示、恢复并激活主窗口。
- `--show`：显示并激活主窗口。
- `--tray`：静默驻留，用于开机启动。
- 已有实例时再次启动：广播唤醒消息；已有实例显示、恢复并尝试置前。

## 模板体检

保存模板前继续调用引擎提供的体检逻辑。至少保留以下检查：条件规则无条件、条件或解析目标悬空、规则结果为空、可证明永不成立的条件、无效占位符、批量源未选/已删除/类型错误。用户选择取消保存时，应跳转到相关片段；用户明确继续时允许保存，与当前“提醒但不强制阻止”的交互一致。

## 测试与验收

### 自动化测试

- 空源、输入后清空、规则由命中变为失配时，所有无其他来源的派生值清空。
- 非 `empty` 条件对空来源不命中，取反也不命中；`empty` 与“不为空”保持可用。
- 无默认值的单选为空，有显式默认值的单选仍取默认值。
- 单段和多段 `split` 严格截取一致，多段不串行、不残留。
- 批量每个非空源行只生成一个输出行，常量列稳定，派生列逐行变化。
- 固定片段 `\t` 生成实际 Tab；每行列数符合模板定义。
- `data.json` 和交付模板 JSON 可读取、序列化、重新读取且规则语义不变。
- 模板体检既有测试全部保留，并覆盖批量配置错误。
- 文件测试使用 `/tmp` 下的独立临时数据目录，避免真实用户数据和沙箱权限影响结果。

### Windows UI 验证

- 普通双击首次启动显示前台；`--tray` 不显示；第二实例唤醒已有实例。
- 编辑器预览分隔条反复拖到上下限、最大化后拖动、双击恢复，无重叠、残影或负尺寸。
- 编辑所有规则类型及其排序后，预览立即变化。
- 保存模板仍显示逻辑体检提示，并正确定位问题片段。
- 导入交付模板，粘贴 `示例完整.txt`，复制结果到 Excel 或在线表格，每个元素进入相邻独立单元格。

## 非目标

- 不引入正则表达式语言或脚本执行器。
- 不自动修改用户原始告警的字词。
- 不重构与本次规则、编辑器布局、启动行为无关的模块。
- 不改变最多九个并行填写会话的产品限制。
