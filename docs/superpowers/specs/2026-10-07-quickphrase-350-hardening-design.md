# QuickPhrase 3.5.0 深度修复与规范化设计

状态：用户于 2026-10-07 确认本书面设计；实施计划及执行方法待审阅。依据：[深度审查](../../3.5.0-deep-audit.md)、[开发规范](../../DEVELOPMENT.md)。本文件不表示代码已修复或原生 Windows 验收已通过。

## 1. 目标与边界

目标：修复审查确认的数据完整性、查表、编辑事务和显示缺陷；系统整理全部产品引导文案；在不删除功能的前提下减少无效重算与资源占用，并建立可重复的发布检查。

保留 C11＋原生 Win32、旧 JSON、条件 > 解析 > 引用 > 手填 > 显式默认值的优先级、快捷键、便携和安装交付、Windows 7 构建目标及现有系统 DPI 感知策略。版本仍为 3.5.0，唯一源头 `src/platform/version.h`，manifest 同步四段版本。

不引入 GUI 框架或运行时依赖，不重生成已入库图标母图，不删除图标尺寸，不批量替换用户模板业务内容。不自动提交、推送、回退或删除工作区原有修改、旧安装包和用户资料。开发在当前已有工作区与分支继续。

成功标准是逐项缺陷的失败回归转为通过、可解释的尺寸和性能对照，以及明确分层的验收报告；不承诺“所有潜在缺陷都已被发现”。

## 2. 数据与所有权：完整候选后提交

模型克隆、JSON 读取与序列化采用同一约定：要么返回完整拥有所有权的对象，要么清理全部中间结果并返回失败。禁止跳过分配失败的片段、规则、条件、选项、表引用或 JSON 字段后继续报成功。

- clone 保持原始 id、顺序和已有语义，检查每个子对象和字符串分配。失败不得进入编辑或替换原模板。
- JSON 构建检查对象、数组、字段、UTF-8 转换及添加操作的结果；明确 cJSON 添加失败时的所有权，既不泄漏，也不双重释放。候选不完整时不进入文件写入和原子替换。
- 读取时分配失败与格式错误都不能发布部分 AppData，不能自动用示例替换原文件。
- 每类深拷贝都使用逐点分配故障注入，验证原模型/文件不变、失败状态被调用者处理、全部中间对象释放。
- 规则提交使用集中的负载转移接口：保留目标节点 id/next，释放旧拥有负载，转移完整候选。查表输出链表的新增、修改、删除、取消都验证所有权。
- 会话保存先完整构造新快照，成功后再换入；失败保留旧快照和当前求值上下文，并明确阻止会丢输入的切换。不能只保留旧指针却随后销毁唯一的新输入。

现有同目录临时文件、写入/刷新/关闭检查和原子替换继续保留。序列化失败、替换失败分别验证，不能用“文件写入是原子的”代替数据完整性证明。

## 3. 编辑与设置事务

嵌套规则窗口只编辑自己拥有的工作副本。确定通过验证后一次提交；取消、Esc、标题栏关闭和父窗销毁都释放候选、不修改调用者模型、返回未接受。result 只表示用户接受，dirty 是独立状态，不能混用。

数据表管理是独立操作，其对应用表引用的修改不因关闭查表规则而回滚；界面明确说明这一边界，保存失败保留未保存状态，不显示完成。查表规则对所选表和映射的候选修改仍可取消。

设置区分候选、可撤销运行态与持久化。热键注册失败恢复原热键；保存失败补偿热键、主题和自动启动状态，恢复实际全局设置。补偿本身失败时不能声称“已全部恢复”，显示失败项目并保持对话框可操作。单独执行的数据目录切换不假装属于可由设置窗口取消撤销的操作。

所有保存入口都处理失败，不伪报成功、不退出丢失内存修改。对已在内存中保留的未保存编辑，错误引导说明重试和检查权限/空间的方法；实际已经回滚的操作则说明未提交，而不使用同一条误导性的成功文案。

## 4. 绘制、布局与工作区

截图证明跨子窗口残影，但现有环境不能证明具体的像素保留根因。先修正测试，再用可观测证据选择绘制修复：

1. 原生测试正常调整宽/高、连续缩放、拖预览分隔条和滚动属性区；只泵送正常消息，不为测试对象额外发送整窗失效。
2. 在稳定几何下捕获自然绘制图像，再完整失效并绘制出参考图。比较非光标、非动画区域；记录尺寸、DPI、主题、自然/参考图片及差异范围。
3. 独立诊断父窗尺寸变化的客户区像素保留、布局提交后的子窗口/非客户区失效、兄弟窗口裁剪。不得一次同时改三个机制后将其中之一当成已确认根因。
4. 统一布局提交后的损坏区域处理，保证移动后露出的背景、变尺寸的控件和必要的边框都被正确重画；合并绘制请求，不靠每帧整窗同步重画掩盖错误。

布局继续使用配对的私有队列，原生 Begin/Defer/End 失败时完整重放。几何计算与可见性更新分离，通知重入受嵌套闸门约束。滚动条宽度和内容高度收敛使用有界计算，禁止无保护递归依赖系统恰好稳定。

文字标签保留原生 HWND、文本和键盘/辅助功能语义。长说明按实际字体测量折行，不能以省略号隐藏操作步骤。只读摘要和路径允许选择与滚动；按钮/短标签可保持紧凑，但完整语义须可访问。

缓冲绘制失败时直接绘制正确内容，不能清掉更新区域却什么都不画。必要缓冲按实例管理、随尺寸变化、销毁时释放；是否复用以资源计数与耗时为证据，不引入无限缓存。

窗口首次打开、恢复和最小跟踪尺寸均按 owner 所在显示器工作区限制；不把 880×690 逻辑像素当成所有显示器的物理最低尺寸。支持 1366×768 工作区在 100%/125%/150%/200% 缩放下访问必要操作：压缩固定头部、保持属性滚动、限制预览高度，窗口宽度较小时使按钮行合理折行。客户区宽度低于 800 逻辑像素时，上半区切为「片段」「属性」页签，各自占完整可用宽度；正常宽度保留双栏。模板级名称/分组和保存/取消保持可访问，模板级输出配置仍可在属性页访问。保存/取消始终可见；焦点进入视口外控件时滚入可视区域。不变更 Per-Monitor DPI 策略。

## 5. 查表、缓存与文本正确性

- 建索引和查询使用完整去首尾空白/大小写规范化键，不按 255 字符前缀判断身份。
- 保持精确文本优先；数值兼容使用精确十进制规范形式（有效数字与十进制指数），兼容 007、123.0、科学计数法，不经 double，也不展开巨量零。不同大整数和不同小数绝不能碰撞；非法数字、NaN、Infinity 不进入数值兼容。FIRST/LAST/ALL、去重、原始行顺序保持兼容。
- 逐段查表每个目标独立记录命中次数。成功得到空单元格仍算命中并接管目标，空值保留对应换行；空白键与未命中段沿用旧跳过规则。命中状态不由字符串长度决定。
- 文件读取前后核对状态；中途变化时最多重试 2 次，仍变化则返回可操作错误，不将旧内容标为新时间戳。求值周期使用一致的表快照；刷新不能使仍在使用的借用指针悬空。
- Unicode 的复制、追加、截断和选区不拆 UTF-16 代理对，预览与复制共用原文及失配映射。合法空值不画成未匹配，提示不进入剪贴板。
- 输出容量不能静默切掉内容还显示“复制成功”。保留已有容量约束，新增显式完整/截断/失败状态：发生截断时显示限制和减少内容的办法，并阻止将不完整结果作为正常输出复制。旧核心 API 保留兼容封装，UI 使用带状态的路径。

## 6. 所有引导文案的范围与规范

审查覆盖主窗口、菜单和会话、模板编辑器、解析/条件/查表窗口、数据表管理、设置、预览空态/失配提示、关于窗口、托盘、启动/保存/导入导出错误，以及安装器和卸载器。核心层返回的用户可见错误也纳入。产品名“口径生成器 QuickPhrase”保留；业务模板正文、JSON 字段、用户变量名不做机械替换。

统一规则：

- 使用“模板、片段、变量、规则、数据表、输出文本、表格输出、填写会话”。普通功能引导不混用“口径”“认人”等比喻；产品名称例外。
- 一句话说明状态，一句话说明动作；危险操作说明影响和可否恢复。错误说明已发生的结果、保留情况、可采取的办法，不无依据推断“被安全软件拦截”或“剪贴板被占用”。
- 短标题配必要帮助，使用中文全角标点与「控件名称」，控件引用与实际按钮一致；统一省略号为“…”和明确的快捷键写法。
- 取消语义、未保存状态、规则优先级、合法空值、逐段/批量处理的空行语义必须与实现一致。
- 数据表通过稳定引用关联，不再写“规则按名称引用”；文件更新提示说明自动检测的触发时机，并提供刷新入口。
- 所有可配置热键的引导显示实际配置或明确“默认”，不将 Alt+Q 写成固定事实。安装器不使用“不到 1 MB”等随产物变化的宣传断言。
- 引导文本变化必须同步重新测量布局；避免为降低字数删除关键限制，或把说明藏在省略号中。

统一表达示例：

- 重名变量：“变量名称重复。请为每个变量设置不同的名称，以便引用和占位符准确匹配。”
- 复制失败：“复制失败。请稍后重试；如果仍无法复制，请减少输出内容或检查剪贴板是否可用。”具体原因可取得时显示具体原因。
- 查表更新：“覆盖原数据表文件后，下次查询会检测更新；如结果未更新，请点击「刷新」。”实际按钮存在的位置才引用该按钮。
- 未选数据表：“尚未选择数据表。请点击「管理数据表…」导入文件，再返回选择。”
- 取消规则：“取消将放弃本窗口的规则修改。通过「管理数据表…」完成的数据表操作不会撤销。”

实施时建立逐窗口文案清单（源码位置、类型、旧/新文案、对应行为与布局验证），全部项目必须有已修改或理由充分的保留结论。共享重复文案用轻量常量/函数复用，不为此引入国际化运行库；功能特有引导就近维护。清单及语义/控件引用检查纳入回归，不能仅靠搜索几个口语词宣布全部规范化。

## 7. 性能、减重与文件职责

先记录输入通知、求值、查表、预览模型更新及绘制次数和耗时，再减少无变化重算：同一预览内容/失配标记不清选区、不回顶；尺寸变化只排版，主题变化只绘制。必要输入事件可合并，但复制和确定操作同步处理最新输入，不能输出旧结果。

复用求值工作缓冲；同一查表键多个输出复用一次行结果；FIRST/LAST 避免收集全部重复命中。避免为了缓存引入新状态污染或不受限内存增长。

按职责拆出编辑事务、布局/滚动和绘制策略，保留核心/UI/平台分层，不做只改目录名的拆分。新增接口明确所有权、失败返回和重入边界；采用 `Qp`/`qp_` 命名，公共入口与私有接口分开。

构建先去除未使用的重复图标组，保留原九尺寸；关闭 cJSON DLL 导出。评估 UI `-Os` 与核心 `-O2` 或整体 `-Os`；LTO 仅在体积和性能都验证后启用。不要移除 x64 展开信息、改变最低系统目标或关闭必要格式化能力来节省空间。

体积发布预算：主程序 ≤448 KiB，安装包 ≤576 KiB；超预算构建明确失败并报告代码/资源/嵌入文件的增量，调整预算须有理由与确认。优化目标参考为临时保守构建主程序 377 KiB，非未经验证的硬承诺。诊断工具单独统计，不混进主程序或安装包。

性能门槛：同工具链、同固定合成夹具下，记录普通模板、100/500 片段模板、4000 条正则模式、10万行表的首次加载和重复查询。候选构建稳定重复运行 5 次取中位数，核心热点相对 O2 基线退化超过 10% 时，不采用该组合；内存峰值和首次启动另行记录，不用磁盘体积代替性能指标。Windows UI 耗时与 GDI/USER 资源计数仍需原生验证。

## 8. 验证、规范与交付

每项修复先增加可失败回归，确认失败原因后再改实现。分配/文件/系统 API 故障注入按所有权边界验证清理、旧状态保留和保存失败。套件共享固定临时夹具时串行运行；临时实验用唯一目录。

必须执行 `make test`、默认 `make sanitize`、`make setup`、内嵌 manifest/图标/安装器文件资源检查、`git diff --check`。LeakSanitizer 不支持 ptrace 时保留失败日志并列未完成；另跑 ASan/UBSan 不得称为泄漏检查通过。

原生 Windows 发布门槛：自然绘制对照、四档 DPI 字体和说明、低工作区可访问性、连续拖动/缩放/滚动、主题、取消/保存失败、实际业务模板、选择复制、EXE/Shell 图标、安装覆盖升级与卸载保留数据。没有真实系统或业务夹具时明确待验收，不发布“全部修复完成”的结论。

交付仍为绿色版、安装包、校验和、可独立运行的诊断/原生测试程序及更新的修复报告。报告逐项区分“探针已复现、修复后回归、模拟契约、真实 Windows 通过、未执行”，记录最终字节数、性能对照、文案清单与限制。不以旧日志代替最新代码的验证。

## 9. 阶段与审阅

实施顺序：数据安全/事务 → 绘制与工作区 → 查表/文本 → 全量引导文案 → 性能/减重 → 完整回归与发布审查。文案清单从第一阶段持续维护，实际修改随相应行为修复同步完成，最后核查覆盖率。

本书面设计审阅通过后，拆为可独立回归的实施任务，明确文件、接口和失败测试。建议继续由本会话主代理实施，最后独立审查；在实施计划审阅时确认执行方法。当前只新增设计文件，尚未改生产代码或替换发布包。
