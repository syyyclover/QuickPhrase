# 开发规范

## 工程与职责

- C11（MinGW 使用 gnu11 兼容 Win32 扩展），UTF-8 源码、LF 行尾；不引入运行时框架。
- `src/core`：纯 C 模型、规则求值、输出渲染、检查、查表、正则、Unicode 与文本排版。
- `src/ui`：主窗口各职责模块、各类对话框及自绘预览。`ui_internal.h` 与 `dialogs_internal.h` 仅供 UI 内部使用；公共入口保留在 `ui.h`。
- `src/platform`：进程入口、系统托盘、热键、启动策略、应用状态与统一版本号。
- `third_party/cjson`：第三方代码与原始 MIT 许可声明，不混入应用逻辑。
- 核心的内部跨模块接口仅写在 `engine_internal.h`；不依赖 `windows.h`。存储和表格文件访问用条件编译隔离平台调用。
- 编辑器上下文在 `editor_internal.h`，外层几何及属性滚动在 UI `editor_layout.c`，纯几何在核心同名模块。固定模态窗口的工作区视口独立于原有内容布局。
- UI 主状态在 `main_state.c` 中定义；会话仅拥有 id 和输入快照，不拥有模型对象。数据释放前先清理活动 UI 引用。

## 数据和交互约定

- 保存沿用现有 JSON；不增加必填字段。条件 > 解析 > 引用 > 手填 > 显式默认值；不保留失效的派生值。
- `*_create/clone/alloc` 返回拥有所有权的对象，调用方使用相应 `free/destroy`；缓存表返回借用指针，刷新、切换或失效后不可继续使用。
- 求值、预览和复制使用同一条渲染路径。批量输出使用独立求值上下文。
- `qp_eval_render_checked` 返回完整、截断或失败状态；不完整内容不得以正常成功路径复制。截断仅沿当前输出的声明依赖传播，未使用的 `no_output` 字段不应阻塞完整输出。
- EvalContext 拥有工作缓冲；拷贝字段不拷贝其工作区。`QpTableMatch` 拥有查询结果但借用表，须在配对的 `qp_table_read_begin/end` 范围结束前释放。FIRST/LAST 不创建全部行数组，ALL 延迟构造一次有序结果。
- 模型和 JSON 候选必须完整；任何必需分配失败须释放候选并返回失败，不得跳过条目发布残缺成功。先准备新快照/设置候选，再提交；补偿失败须报告实际状态。
- Unicode 截断必须保留完整字符。输入控件上限为模型容量减去结束符，较小字段需显式设置上限。
- 保存错误必须向调用方返回；失败不能显示成功或直接退出并丢失内存修改。损坏的已有数据不得自动用示例数据替代。
- 文件通过同目录临时文件写入并替换；替换失败保留原文件。切换目录先验证和持久化，最后再提交内存状态。
- 表格的失败提示来自引擎元数据，普通空白单元格不表示规则失败。提示不进入复制原文。

## 布局与绘制

- 使用 `qp_layout_begin → qp_defer → qp_layout_end`；返回值是私有队列，不可交给原生 `EndDeferWindowPos`。原生批处理失败时队列重放全部请求。
- 纯位移不使用 `SWP_NOCOPYBITS`；尺寸变化时使用。父窗口裁剪子控件，自绘窗口双缓冲；无 WM_PAINT 的窗口失效需正确擦除背景。
- 列表程序化重建使用可嵌套 loading 闸门，避免同步通知重入。模型同步产生的 EN_CHANGE 不得写入用户输入。
- 文本折行、绘制、选区和鼠标命中共用逐字符字体度量；Tab 的显示展开与复制原文分开。
- 保持原生布局、现有快捷键和系统 DPI 策略。本版本不升级为 Per-Monitor DPI 感知。
- 文案说明当前状态和可采取的动作，统一使用模板、片段、变量、规则、数据表等术语。
- 长说明使用 `mk_wrapped_label` 与实际字体度量，交互摘要使用可选择的只读多行控件；不得靠省略号掩盖操作说明。普通 Static 局部缓冲绘制，不使用整窗复合绘制。
- 显隐状态与几何计算分开；用 `qp_show_if_needed`、列宽和滚动信息比较避免重复更新。规则布局由 `src/core/rule_layout.c` 计算，UI 负责字体测量与应用队列。
- 超出 owner 工作区的固定模态窗口保留原物理内容尺寸，使用独立滚动视口和焦点显露；不可把固定子控件直接裁小。数据表/解析规则的可缩放窗口在小工作区使用最小虚拟画布，布局取 `qp_dialog_content_rect`，控件通过 `qp_dialog_defer` 配对队列摆位，跟踪尺寸不能大于工作区；编辑器继续自己的响应式布局。子类引用随根窗口销毁释放，EnumChildWindows 的结果通过回调状态检查，不能把其返回值当成功标志。
- 同内容、格式及失配标记的预览刷新不清选区、不回顶、不重建模型；字体/DPI 变化需重新度量，尺寸仅排版，主题仅绘制。绘制缓冲失败仍须正确直接绘制。
- 预览内容 setter 返回发布成功状态，模式/模型/原文共同提交；失败保持旧代际，不先切模式。复制操作重新渲染后必须成功发布同一代际，否则拒绝复制并禁用复制按钮。多选超限的勾选原子回退；打开模板编辑器前先保存活动填写快照，模态期间不得异步修改 owner 输入。

## 构建与验证

```sh
make -j4 test       # C 单元测试 + 正则差分 + OS 模拟/布局契约检查
make -j4 sanitize   # clang ASan/UBSan，不能关闭泄漏检测来掩盖错误
make -j4 setup      # 绿色版、卸载器、安装包
make win32-test     # 真实 Win32 调用，在隔离 Wine/Xvfb 环境运行
make icons         # 仅将已入库 AI 母图打包为多尺寸 ICO，无网络调用
make icon-check    # 构建 Windows 单文件图标诊断工具
make bench         # 固定合成夹具，交错五次中位数（不是 Windows 性能验收）
make check-size    # app ≤458752 B，setup ≤589824 B
```

Windows 可在全新的测试用户配置中运行 `build/test_win32.exe`。它会使用真实 HWND、消息、GDI、剪贴板及模态窗口并保存测试几何设置；检测到已有 QuickPhrase 数据、设置或窗口时会拒绝运行，避免覆盖用户配置。Wine 通过也不能替代原生 Windows 的安装升级和视觉验收。

修复前添加能复现缺陷的失败测试；修复后执行相关测试，模块拆分后运行完整套件。缺少真实业务夹具必须报告跳过。测试报告必须区分纯算法、API 模拟、Wine 和原生 Windows，不得混称为 GUI 已通过。

若 LeakSanitizer 明确因 ptrace 沙箱不支持而终止，须保留默认失败日志并将泄漏验收列为未完成；可另行执行关闭泄漏检测的 ASan/UBSan 检查，但不得称为完整 `make sanitize` 或泄漏检测通过。图标诊断的 DIB 像素读取须先完成 GDI 同步；本机 `--self-test` 用不同图标检查实际批处理输出。

版本唯一源头为 `src/platform/version.h`；同步 manifest 的四段版本号和文档产物名称。`tools/snapshot.sh` 创建唯一目录并保留已有快照；不要运行覆盖用户修改的清理命令。

默认构建核心 `CORE_OPT=-O2`、UI/平台/安装器 `UI_OPT=-Os`、`LTO=0`，隐藏 cJSON DLL 导出；版本不靠优化选项改变。对象目录带参数指纹，切回既有配置仍通过活动配置记录触发重新链接。不同配置同时构建须使用不同 `BUILD`/`DIST`，安装资源从相应构建路径内嵌。不删图标帧、x64 展开信息或最低 Windows 目标来凑体积预算。

产品引导清单在 `docs/ui-copy-review.json`，记录原文/当前文案、来源哈希、审阅结论、行为与布局验证。`tools/audit_ui_copy.py --check` 拒绝未审阅或失效记录、错误按钮引用；当前覆盖 CJK 字面量，动态用户内容和新非 CJK 文案仍需人工审查，清单不证明原生字体/视觉通过。

分配故障驱动使用 GNU linker wrapping；优化编译下计数必须可观察，驱动禁用相关 allocator builtins，计数为 volatile，诊断头也是构建依赖。这个设置只用于故障驱动，不改变发布核心优化。模拟 OS 调用仍不得标注为真实 Win32 验收。

manifest 是独立 XML，不能写 C 宏；版本属性必须是带引号的四段数字。`make check-manifests` 检查源 XML；程序和安装包构建后还必须用 `tests/manifest_validation.py` 检查内嵌 RT_MANIFEST，不能只检查 VERSIONINFO 或 windres 成功。
