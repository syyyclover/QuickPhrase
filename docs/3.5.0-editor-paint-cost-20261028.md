# 编辑器背景与列宽绘制开销

用户确认上一轮候选已无黑块，但拉边框、最大化仍不如主界面流畅，不能标为性能验收通过。

对第二轮日志 `resize-timing-28992.csv` 的嵌套阶段进一步对齐：外层几何提交结束至属性布局开始，平均间隔 13.779ms，最高 35.001ms。该区间的生产代码仅调用片段列表的 `qp_set_column_width_if_needed`。这是完整布局平均 44.479ms 中尚未单列的主要开销之一。

本轮改动：

- 列宽变化时，在可见列表上配对暂停/恢复重绘，阻止列宽消息立即绘制，保留完整失效标记供布局末尾统一绘制。无需改变列宽时不操作；隐藏列表不改变可见性。实际暂停范围仅包围列宽 setter，几何队列仍使用上一轮实现。
- 编辑器背景请求不与分隔线相交时，直接完成一次纯色填充，避免每次新建 DC/位图、复制和释放。含分隔线的区域保留原双缓冲及分配失败回退；主窗口背景绘制和防黑块的呈现事务不变。
- 属性区等纯色宿主的 WM_PAINT 也采用一次 FillRect 完成画面，不再创建整客户区位图。该公共宿主绘制函数同样用于主窗口填写区；子窗口和更新区仍由 BeginPaint 的 DC 裁剪。这不是将背景擦除改为空操作。
- 计时副本增加 `segment.column` 项，便于原生手工复测定位变化。

`column_resize_paint.py` 与 `editor_paint.py` 都已确认原实现先失败、修正后通过。绘制回归覆盖分隔线上下及左右边界、整窗含线绘制、DC/位图/画刷分配失败、空区域；列宽回归覆盖无需变更、隐藏、负宽度和空句柄。编辑器 50 个几何案例及主窗口绘制回归通过。适配测试和静态审查不能证明真实 ListView 行为或流畅度；没有启动桌面自动测试。

本机诊断候选在 `dist/editor-paint-cost-trace-20261028/`；原工具链程序和安装包在 `dist/editor-paint-cost-20261028/`。

首次完整测试因几何模拟器缺少新增 Win32 API/常量而中断，补齐后通过。初次打包体积检查显示主程序超出预算 512 字节；未修改预算、优化参数或资源。随后将分隔线几何计算复用，并删除纯色宿主无必要的离屏绘制，再次验证。宿主无分配回归使用实际生产函数，确认旧函数失败、新函数通过。

最终源码在 Linux 原工具链顺序通过 `make test`、默认 `make sanitize`（含泄漏检查）、`make setup`；内嵌资源和体积检查通过。原有两组业务夹具缺失、正则压力档差异及适配驱动未使用变量警告保留。日志在 `build/editor-paint-cost-results/`。静态复核未发现重要问题，但当前候选仍未完成原生流畅度与视觉验收。
