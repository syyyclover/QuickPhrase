# 编辑器拉伸卡顿补修（2026-10-28）

用户反馈模板编辑器拖边框、双击最大化明显卡顿，而主窗口没有同样问题。

本次对比定位到上一轮编辑器补修中的两处额外绘制开销：

- `ed_layout` 已完成几何损伤和待处理子窗口绘制，`WM_SIZE` 又无条件失效并同步重画全部子控件。最大化时呈现完成函数还会再完整绘制一次，造成重复工作。现在删除 `WM_SIZE` 中多余的整窗重绘，保留布局损伤处理以及最大化呈现前的完整绘制。
- 编辑器 `WM_ERASEBKGND` 忽略传入 DC 的裁剪范围，按完整客户区创建离屏位图。逐个移动子控件会触发多次父背景擦除，大窗口时每次均分配、填充大位图。现在按 `GetClipBox` 处理，仅在接口返回 ERROR 时回退完整客户区，仍在同一缓冲中绘制背景与分隔条。正常 `WM_PAINT` 继续使用 `rcPaint`。

新增 `editor_resize_cost.py`，旧代码因二次同步整窗绘制而失败，删除后通过；覆盖尺寸未变、最小化跳过和仅保存还原尺寸。`editor_paint.py` 增加裁剪分配断言：擦除/取图使用 40×30 的裁剪位图，而非 800×600 全客户区，并保留 DC/位图/画刷失败回退检查。`editor_resize.py` 检查最大化呈现时序和重试路径。这些是 OS 适配验证，不是原生视觉或拖动延迟测量。

按用户此前停止视觉测试的要求，本轮不弹出自动测试窗口。最终原生手工流畅度及黑块回归仍需复测。主窗口逻辑和共享呈现函数未修改。

复核补充了超出客户区的打印 DC 和空交集回归：裁剪范围先与客户区相交，空交集不绘制，避免覆盖调用者画布的其他区域。新增回归先失败、修正后通过。
