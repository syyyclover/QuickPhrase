# 编辑器宽度变化专项定位

用户反馈内部 UI 分隔条拖动流畅，最外层左右边框和四角明显卡顿，单独改变高度不是主要问题。因此不能把卡顿笼统归因为外框消息循环，也不能把先前优化当作完成。

最新 `resize-timing-30256.csv` 的缓冲溢出，丢弃 69681 条记录。已保留样本仅含 24 次外层尺寸布局，平均 56.43ms；内部布局只有 2 次，不足以比较。片段列宽阶段平均 5.45ms，最终绘制平均 22.56ms。59543 条 WM_NOTIFY 总计约 1.083ms：它们占满日志，但不是主要耗时证据。不同操作样本、窗口尺寸与日志截断也不支持用整体均值断言回退或改善幅度。

本轮不改正式显示逻辑，仅调整 `tools/build_resize_trace.py` 的隔离副本插桩：

- 根窗口仅记录尺寸、绘制与拖动相关消息，过滤通知、颜色查询、辅助功能请求等噪声。
- 为编辑器子控件安装诊断子类，记录尺寸、绘制、背景、非客户区和列宽消息；附带控件 ID、窗口类名与客户区尺寸，不记录文本内容。
- 继续内存缓冲，关闭编辑器后写 CSV；统计为嵌套跨度，不能直接相加。插桩也有开销，不能等同无插桩发布程序的精确帧时间。

诊断版为 `dist/editor-width-trace-20261028/QuickPhrase.exe`。本机编译、内嵌 manifest 和图标校验通过，无编译警告；未运行桌面自动化，也没有因仅改变诊断副本而重跑正式完整测试/安装包。建议一次编辑器会话依次拖底边、右边、内部预览分隔条各约两秒，再最大化/还原一次后关闭窗口。分析将按尺寸变化和控件 ID 区分宽度相关工作。
