# 窗口恢复瞬间黑块补修（2026-10-28）

后续用户复测仍能触发黑闪。本报告的擦除帧验证不能证明恢复呈现无黑闪；新的呈现时机修正、屏幕取帧结果和产物见 [3.5.0-restore-publication-20261028.md](3.5.0-restore-publication-20261028.md)。

## 用户验收状态

用户提供截图并明确：黑块只在窗口恢复瞬间闪过。上一轮 `bugfix-20261028` 的视觉验收失败，补充主窗口重绘请求没有解决这一现象。本轮验证修正后的擦除帧，不将其等同于 DWM 动画期间的屏幕视觉验收。

## 定位与修正

截图中的预览区短暂呈纯黑。生产预览窗口和会话标签窗口的 `WM_ERASEBKGND` 直接返回 1，没有在传入的 DC 上绘制任何像素；主窗口/填写区已有的重绘修正没有补全这两类子窗口的擦除路径。

新增 `tests/test_restore_frame_win32.c`：创建真实但隐藏的 HWND、真实 32 位 DIB 和 GDI 画布，先取得完整绘制的参考帧，再从全黑画布调用生产窗口的擦除消息，逐字节比较像素。覆盖浅色/深色、文本/表格预览、实际会话标签模型、完整/局部裁剪；参考帧必须含前景文字像素。同步检查 DC 裁剪和正常待绘制区域没有被改变。

保留原生产文件构建基线，同一最终测试程序对照结果：

- 修复前：763 项检查，240 项失败；擦除报告成功，但画布仍黑。
- 修复后：763 项检查，0 失败。

`preview.c` 和 `main_sessions.c` 中的擦除消息现与 `WM_PRINTCLIENT` 共用完整双缓冲绘制，绘制背景和文字后再提交像素，保存/恢复调用方 DC 状态；擦除返回 1，取图绘制仍返回 0。没有消耗正常 `WM_PAINT` 区域，没有改变模型、复制路径、布局、系统动画或用户数据。

- 本机 Windows 原生回归通过。除本机工具链构建外，还使用与交付程序相同的 MinGW 发布对象构建该测试，取回 Windows 实际运行：763 项检查、0 失败。测试无可见窗口、无交互消息循环、不读写用户配置、不操作剪贴板。
- `paint_failures.py`、`window_print.py` 新增擦除阶段的回归，Linux 上旧生产代码均先失败，修正后通过；覆盖 DC/位图分配失败后的直接绘制。这两项是 OS/GDI 适配检查，不称原生 Windows 验收。
- Linux 构建机依次执行 `make -j4 test`、默认 `make -j4 sanitize`（未关闭泄漏检测）、`make DIST=dist/restore-frame-20261028 -j4 setup`，全部通过；使用普通用户和隔离 `/tmp`，未改动旧固定夹具。
- 发布代码无编译警告，manifest、图标载荷、程序/卸载器内嵌、体积检查通过。程序 458752 字节，安装包 595456 字节；未调整构建优化或已有体积预算，未生成图像。
